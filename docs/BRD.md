## 1. 背景与机会

### 1.1 用户痛点

个人投资者面对财报的三大断点：

| 断点 | 现状 | 后果 |
|---|---|---|
| **读不下去** | 财报 PDF 动辄 200 页，`2,345,678,901.23` 式巨长数字、密集双栏表格，通用 PDF 阅读器零辅助 | 打开即弃，季度跟踪无从谈起 |
| **读不懂** | 科目术语、口径变化、附注迷宫；通用 AI 工具对财报数字精度与出处无保障，幻觉风险高 | "AI 替我读"生成一份漂亮报告，用户仍不敢信 |
| **记不住** | 一家标的车 8 份季报 + 每年几十份公告，事件散落各处，无法纵览"这家公司到底发生了什么" | 决策靠印象而非证据链 |

### 1.2 市场空白

- **商业 AI**（扣子空间/元宝/ChatDoc 等）走的是**替代读**路线：上传 → 生成分析报告。快，但用户失去原文与判断力，数字无引用保障，且不开源。
- **开源项目**集中在**解析层基建**（MinerU 等 PDF→Markdown），不做阅读产品。
- **"阅读体验 × 财报特化 × 多文档编年"** 这个组合没有任何玩家占据：
  1. 读书软件级阅读体验 + 财报特化（数字可读化/科目词典/单季拆分）——无人做
  2. 跨多期财报与公告的事件梳理与时间轴——无人做
  3. 开源 + 中国数据源（巨潮/A 股口径）——无人做
- **信任红利**：投资工具不开源难以获得个人投资者信任；开源是这个市场的差异化武器而非负担。

### 1.3 时机

- AIGC 工具普及让"AI 伴读"成为被普遍接受的交互范式；
- 中国《人工智能生成合成内容标识办法》（2025-09 施行）确立了 AI 内容标注规范，合规路径清晰；
- 财报 PDF 是高度格式化的公开披露文档（相比古籍/扫描件），程序化预处理与引用溯源可行性极高；
- 目标社区（知乎/雪球个人投资者）存在成熟的"产品故事帖"冷启动路径。

## 2. 产品定位

> **句读：开源的 AI 财报伴读器 + 标的编年史。**
> 给财报断句，给标的编年。

"句读"（jù dòu）是古人断句之法——古书无标点，不会断句就读不懂文章。财报是现代的无句读之文：巨长数字、密集表格、散落各期的事件。产品的每个功能都在做"断句"：数字断成亿、版面断成速览、术语断成白话、时间断成编年轴。品牌语出自韩愈《师说》：**"句读之不知，惑之不解。"**——财报之不知，惑之不解。

三层价值：

| 层 | 动词 | 功能带 | 用户价值 |
|---|---|---|---|
| **读** | 读原文 | 阅读器 / 获取导入 / 数字可读化 | 财报能读下去 |
| **懂** | 读得懂 | 逐页速览 / 划词问答 / 多层 AI 解读 | 财报读得明白 |
| **记** | 记得住 | 读后综合 / 标的档案与编年时间轴 | 标的看得穿，决策有依据 |

产品四铁律（不可妥协的设计宪法）：

1. **伴读不替读**——原文恒在，AI 是侧栏、悬浮与注，永不替代原文
2. **有据必引**——AI 回答必须引用页码/公告链接，无据即答"不知道"
3. **数字程序算**——换算与统计由程序完成，AI 只解释程序算好的数
4. **整理不荐股**——影响方向是信息整理属性，判定权与最终决策永远在用户

## 3. 目标用户与画像

| 画像 | 场景 | 付费/使用意愿 | 规模判断 |
|---|---|---|---|
| **个人投资者**（核心） | 财报季集中阅读、季度跟踪持仓、建仓前深研 | 高（时间稀缺、有信息焦虑） | A 股个人投资者过亿，活跃财报阅读者百万级 |
| 研究员/分析师 | 深读 + 产出笔记 | 中（引用可信是刚需） | 长尾 |
| 学习者 | 学读财报 | 中（引导式导读） | 长尾 |
| 开发者/极客 | 自部署、二开、贡献模板 | 低付费高传播 | 开源社区杠杆 |

**核心用户旅程（一句话）**：财报季 → 搜标的 → 一键拉取全部历史财报与公告 → 先看编年时间轴知道发生了什么 → 打开本期财报，速览 + 数字悬浮 + 划词问答深读 → 读完综合入档 → 时间轴延续，自己做出判断。

## 4. 竞争格局

| 竞品 | 类型 | 核心能力 | 句读的差异 |
|---|---|---|---|
| 扣子空间财报分析 | 商业 AI | 上传→10 分钟出报告 | 它替代读，我们辅助读；它不开源，我们开源可自部署 |
| 腾讯元宝/KIMI/ChatDoc | 商业 AI | 通用长文/ PDF 对话 | 无财报专属能力（科目词典/单季拆分/编年轴），数字精度与引用无保障 |
| Wind/iFinD/Choice | 机构终端 | 数据+原文俱备 | 昂贵、无 AI 伴读、不开源；反衬句读"开源+免费+伴读"卡位 |
| 财报阅读类浏览器插件 | 插件 | 网页财报转文本喂 AI | 无自有阅读器，体验割裂 |
| MinerU 等解析基建 | 开源 | PDF→Markdown | 是可插拔的解析引擎之一，不是竞品 |
| 东方财富/问财 | 数据平台 | 查数据 | 不是"读原文"场景 |

**竞争策略**：不做 PDF 解析轮子（可插 MinerU/自研轻量规则），专注「阅读层 + 财报理解层 + 多文档编年层」；中文财报场景（巨潮/ A 股口径/科目别名）做深形成天然区隔。

## 5. 商业模式

**阶段一（当前～验证期）：全免费 + 成本转移**

- 云端注册用户享免费配额；重度用户 BYOK（自带 LLM key）无限用——平台 key 只做体验额度
- 内容寻址去重（公共公告 PDF 与预处理产物全站共享一份）把边际成本压到接近零
- 最坏成本估计：100 活跃用户 × 月 10 份新财报 × 0.5 元 ≈ 500 元/月；BYOK 分流后百元级
- 基础设施：Vercel Hobby + Supabase 免费层 + R2 免费层（10GB）

**阶段二（验证后）：轻变现，三选一或组合**

1. 云托管增值（更高配额/更多标的档案数订阅）
2. 商业授权双轨（核心 AGPL-3.0 + 付费商业许可，面向机构）
3. 社区赞助（GitHub Sponsors/爱发电）

**永不做**：卖投资建议、卖用户数据、投顾业务——合规红线即商业边界。

## 6. 成功指标

| 层 | 指标 | 说明 |
|---|---|---|
| **北极星** | 周完整阅读财报数（读到最后翻页的文档数） | 唯一能证明"读得下去"的指标 |
| 价值确认 | 标的档案创建数 / 时间轴周活浏览数 | "记得住"被使用 |
| 传播 | GitHub star / 产品故事帖转化（阅读→注册） | 开源获客漏斗 |
| 深度 | BYOK 转化率 | 重度用户信号 |
| 质量 | AI 回答引用率（100% 为目标）/ bad case 提交数 | 信任的基础设施 |

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 巨潮接口限流/封禁（站内下载是核心卖点） | 高 | 接口层抽象可换源；hash 缓存；失败降级手动上传；监控告警 |
| 投顾合规边界（时间轴"利好/利空"最敏感） | 高 | 产品级设计：影响方向+依据+用户改判+免责声明，永不出现买卖措辞（详见 PRD §3.8.4） |
| AIGC 标识义务 | 中 | 所有 AI 输出统一挂"AI 生成"标识（法规已施行，路径清晰） |
| LLM 成本滥用 | 中 | 配额+限速+BYOK+单文档预算+全站缓存 |
| 大厂跟进（元宝加财报模式） | 中 | 开源+自部署+社区模板库是个人项目对抗大厂的正确姿势；速度与社区是护城河 |
| 单人开发带宽 | 中 | 里程碑严守范围；规则层先行、LLM 层渐进；坏案例社区共建 |
