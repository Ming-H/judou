## 1. 愿景与定位

### 1.1 一句话

> **句读：开源的 AI 财报伴读器 + 标的编年史。**
> 拖入或一键下载财报 PDF，像读书软件一样读原文；AI 帮你断句——亿级长数字翻成明白话、逐页速览、划词问答；读完沉淀入标的档案，以时间轴看一家公司从过去到现在发生了什么、什么是利好什么是利空，支撑你自己的决策。

三层价值，一层比一层深：

| 层 | 动词 | 功能 | 用户价值 |
|---|---|---|---|
| **读** | 读原文 | F1 阅读器 / F2 获取导入 / F3 数字可读化 | 财报"能读下去" |
| **懂** | 读得懂 | F4 逐页速览 / F5 划词问答 / F6 AI 解读 | 财报"读得明白" |
| **记** | 记得住 | F7 读后综合 / F8 标的档案与编年时间轴 | 标的"看得穿"，决策"有依据" |

### 1.2 命名决策：为什么叫「句读」

**句读**（jù dòu）：古人断句之法。古书无标点，读书第一课就是"习其句读"——不会断句，就读不懂文章。

财报就是现代的"无句读之文"：
- `2,345,678,901.23` 是无句读的数字 → 断成 **234.57 亿**
- 密集的双栏表格是无句读的版面 → 断成 **逐页速览**
- 术语是无句读的语言 → 断成 **划词白话**
- 散落在 8 份季报 40 份公告里的事件是无句读的时间 → 断成 **编年时间轴**

韩愈《师说》：**"句读之不知，惑之不解。"**——财报之不知，惑之不解。产品的每一个功能都是在做"断句"这件事，名字即产品哲学：

| 功能 | 断的是什么 |
|---|---|
| F3 数字可读化 | 数字句读 |
| F4 逐页速览 | 段落句读 |
| F5 划词问答 | 语句句读 |
| F6 AI 解读 | 篇章句读 |
| F8 编年时间轴 | 时间句读 |

- **Slogan**（主）：`财报之不知，惑之不解。`
- **Slogan**（辅，用于社区推广）：`给财报断句，给标的编年。`
- **仓库/目录名**：`judou`
- **备选名**（均已在决策中淘汰，记录于此）：读财报（零解释成本但不可商标、搜索被淹没）、译报（"把财报译成人话"，与易宝支付撞音）、财报伴读 FinReader（v2 备选，作英文描述语保留）

### 1.3 三种使用形态（继承 v2，同一代码库）

| 形态 | 场景 | 说明 | 注册要求 |
|---|---|---|---|
| **在线版**（主打） | 打开网站 → 注册 → 导入/下载 → 阅读/跟踪 | Vercel/Cloudflare 免费层 | 邮箱/GitHub OAuth |
| **自部署版** | clone 后本地跑 | `docker-compose up`，数据全本地 | 无 |
| **纯前端版**（降级+引流） | 不注册体验核心阅读 | PDF.js 浏览器端解析 + 自填 LLM key | 无 |

三形态是获客漏斗：访客（纯前端试用）→ 注册用户（云端便利+AI 配额）→ 极客（自部署）→ 贡献者（PR/issue）。

### 1.4 核心原则（继承 v1/v2，一字不改）

1. 用户始终在读原文——**AI 是伴读，不是替读**
2. AI 只做有依据的解释——**回答必须引用页码**
3. **数字由程序计算，AI 只说人话**

新增第 4 条（v3，涉及"利好/利空"功能后必须加上）：

4. **产品组织信息，用户做出决策**——影响方向标注是"信息整理"不是"投资建议"，判定权与最终判断永远在用户。

## 2. 体验基准：读通鉴（dutongjian.com）解构

> 调研来源：小众软件论坛开发者自荐帖（2026-04）、知乎《我是如何用AI开发读通鉴的》（2026-06，作者 icemark）。读通鉴 = 个人开发者用 AI 辅助开发的资治通鉴一站式阅读平台，Flask+Vue，知乎原生传播约 5000 注册用户。

### 2.1 它做对了什么（我们移植什么）

| 读通鉴的设计 | 背后的洞察 | 句读的移植 |
|---|---|---|
| **原文 + 多注家分层**（胡三省注 / 张居正直解 / 陈垣胡注表微 / 毛泽东批读 / 通鉴纪事本末） | 一部原文，历代"巨人肩膀"式注释分层挂载，读者按需展开 | **F6 注家系统**：财报原文 + 多套解读模板（速览注/结构导读/框架核对），原文恒在，注可开关 |
| **人物 ID 化**，一键追踪上下文、人物关系、动态年龄 | 实体消歧后，散落全书的同一实体可聚合追踪 | **F8 实体追踪**：子公司/大客户/产品线/科目 ID 化，跨文档一键追踪（"宁德时代在本期财报出现 3 处"） |
| **语义增强双模式**：线条模式（人物加粗/地点加框/官职小字）与颜色模式，可开关 | 在原文上叠加语义层，但把打扰度交给用户 | **F3/F1 叠加层**：数字高亮/科目高亮/实体高亮，线条与颜色双模式，默认克制 |
| **决策卡**：提取历史重要决策，读者"重新体验与决策" | 代入式学习，hindsight bias 的解药 | **F8.5 复盘卡**（远期）：时间轴上每期财报是一个决策点，"回到当时，只有当时的信息，你怎么判断？" |
| **不注册可正常读，高级功能（古本/批注/AI）需注册** | freemium 分层：先给足价值，再要注册 | F1/F2/F3 基础阅读不注册可用；AI 配额/档案/时间轴/云同步需注册 |
| **"软件是壳，内容是芯"** | 开发者的时间花在数据管道而非 UI | 我们的芯 = 巨潮管道 + 预处理 + 数字索引（§7），UI 用现成组件快速拼 |
| **PWA 可安装** | 免 App Store 成本获得类原生体验 | F1 直接做 PWA |
| **知乎原生增长**（产品介绍帖 5000 用户） | 内容营销带产品，一篇好帖冷启动 | §11 运营策略以此为范本 |

### 2.2 它踩过的坑（我们直接绕开）

读通鉴作者的工程教训对句读同样致命，提前写进设计约束：

1. **实体消歧是脏数据重灾区**（他标出过"371 岁的满宠"——AI 把"175年前出生"提成了"公元前175年"）→ 我们的事件抽取/实体抽取全部走"结构化 schema + 置信度 + 抽疑不抽定"原则（§8.3），低置信度数据不进时间轴，进"待人工确认"区。
2. **每份材料的 ETL 都要单独处理**，分析数据的时间远大于写代码 → 财报是**高度格式化**的披露文档（比古籍整齐得多），这是我们的运气；但仍要接受"每家公司的科目口径都有微调"的现实，做**科目别名映射表**而非硬编码（§6.4）。
3. **数据错误无法靠"跑起来报错"发现** → 建立**校验层**：抽取的数字必须能对上 PDF 原文（回显原文片段），对不上的丢弃；时间轴上的每个事件可一键跳回原文页码人工核验。

## 3. 用户与场景

| 用户 | 场景 | 关键诉求 | 对应功能 |
|---|---|---|---|
| **个人投资者**（主） | 财报季集中阅读；季度跟踪持仓；建仓前深研一家公司 | 快速抓重点、数字看得懂、历史可对比、公告事件不遗漏 | 全部 |
| 研究员/分析师 | 深读 + 产出笔记 | 引用页码可信、笔记导出 | F1/F5/F7 |
| 开发者/极客 | 自部署、二开 | 开源协议友好、架构清晰、插件化 | §12 |
| 学习者 | 学读财报 | 术语解释、引导式导读、复盘训练 | F4/F5/F6/F8.5 |

**主场景用户旅程**（一句话版）：财报季 → 站内搜"松发股份"一键拉取全部历史财报与公告 → 先看标的档案时间轴知道"这家公司发生过什么" → 打开本期中报，逐页速览 + 数字悬浮 + 划词问答 → 读到合同负债页存一条笔记 → 读完 AI 综合导读入档 → 时间轴上看到"连续 4 期合同负债上升 + 新签订单公告"，自己做出判断。

### F1 阅读器（读通鉴式体验）

**定义**：像读一本书一样读财报 PDF——保留原始版面（财报表格重排必失真，这是与"解析成 Markdown"路线的根本分野），叠加语义层。

- **渲染**：PDF.js（react-pdf 封装），连续滚动 + 双页/单页切换，缩放自适应
- **目录侧栏**：自动抽取财报章节结构（重要提示/目录/公司简介/财报正文/附注），侧栏导航跳页
- **语义叠加层**（核心技术点，分两档交付）：
  - M1 档：划词触发（选中数字 → 悬浮卡），零坐标依赖
  - M2 档：全文自动高亮（数字/科目/实体），基于 PDF.js 文本层坐标做词级定位；**线条/颜色双模式 + 一键全关**（学读通鉴，打扰度交给用户）
- **批注/高亮/书签**：落在页坐标上，云端同步
- **阅读进度**：记住每份文档读到第几页，文档库显示进度条
- **PWA**：可安装到桌面/手机主屏

### F2 文档获取与文档库

**定义**：两条入口（站内下载 / 手动导入）+ 一个文档库。

- **站内下载（巨潮）**：搜公司名/代码 → 财报（年报/半年报/季报）与公告列表 → 一键入库；**"拉取全部历史财报"按钮**（建仓深研的高频动作）；下载源记录公告 URL/日期可溯源
- **手动导入**：拖拽任意 PDF（财报、公告、甚至研报），站内统一管理
- **文档库**：列表视图（公司/报告期/类型/阅读进度/预处理状态），同一公司多期自动归组
- **去重**：按文件内容 hash，同一份公共公告全站只存一份（见 §7.2，成本关键设计）

### F3 数字可读化（数字句读）

**定义**：财报里 `2,345,678,901.23` 这种巨长数字，悬浮即得可读形式。

**悬浮卡内容**（三层，逐层丰富）：
```
2,345,678,901.23 元
→ 23.46 亿 / 234,567.89 万
→ 若为营收：本期 vs 上期同期（同比 +25.2%）*
→ 百分比换算、每股折算（按最新股本）
```
- 换算**全部由前端程序完成**（核心原则 3），零 LLM 成本、零延迟、零幻觉
- 带 \* 的同比层需要数字索引支持（该数字被识别为已知科目时才显示），M1 只做第一层纯换算，第二层 M2 接数字索引
- **工程风险预告**：数字与科目名的坐标关联（双栏表格里科目名和数字可能不在一行）是本功能最大难点，故 M1 划词版先行，坐标关联版放 M2 且允许覆盖率不满

### F4 逐页速览（段落句读）

**定义**：每页 3-5 条要点，页边栏展示，点击展开。预处理时按页异步生成（Serverless 时限的解法，继承 v2 方案 b），进度条可见，单页失败可重试不阻塞整本。

### F5 划词问答（语句句读）

**定义**：选中任意文本 → 问 AI。默认上下文 = 当前页 ± 2 页；可手动扩为全文档（检索式）。回答强制附页码引用；"读不到依据就回答不知道"（防幻觉硬规则，继承 h1-monitor 实战经验：模型没读到文件时会编造，prompt 必须有 READ_FAILED 类硬约束）。

### F6 AI 解读（注家系统）

**定义**：一份原文，多套"注"，用户按需展开——读通鉴多注家架构的财报版。

| 注家 | 角色 | 输出 |
|---|---|---|
| **速览注** | 字词典故解释（胡三省注位） | F3/F4/F5 已覆盖 |
| **导读注** | 张居正《直解》位 | 全文结构导读：这份财报该重点读哪几节、为什么（基于当期异常科目 + 近期公告事件） |
| **框架注** | 《读通鉴论》位（史论） | 可选框架核对模板：盈利质量/增长来源拆解/风险信号清单等通用分析框架的逐项核对 |

- 框架注做成**开放模板库**（JSON 定义检查项），预置 2-3 套通用模板，社区可贡献新模板——这是开源项目的参与抓手
- 所有 AI 输出带 **AIGC 标识**（合规要求，见 §9）

### F7 读后综合与笔记

**定义**：每读完一份财报，"综合保存"——用户口述需求："每读完一篇财报，可以将内容综合或者保存"。

- **AI 综合卡**：读完后一键生成本份财报的综合摘要（本期核心变化 3-5 条，每条带页码），与用户笔记并列存档
- **用户笔记**：高亮批注 + 自由笔记，挂在文档页码上
- **导出**：Markdown 导出（综合卡 + 笔记 + 引用），可发知乎/雪球的格式

### F8 ★ 标的档案与编年时间轴（时间句读）

**定义**：一标的一档。把该公司全部已入库财报与公告"断句"成一部编年史——用户口述需求："过去读过的财报可以进行融合，以时间轴方式呈现，知道标的从之前到现在发生了哪些重要事情，有什么利好或不好的，让用户据此决策。"

**F8.1 标的档案页**（公司主页）：
- 头部：公司名/代码/行业/最新报告期
- 三区块：**编年时间轴**（主体）/ **跨期科目追踪** / **文档列表**（该标的全部已入库文档）

**F8.2 编年时间轴**：
```
━━━ 松发股份 · 编年史（AI 整理，逐条可溯源）━━━
2026-09-01 [订单·↑] 新接 10 亿美元 PCTC 船订单      ← 点击跳公告原文
2026-08-25 [财报·↑] 中报：H1 营收 235 亿 +252%，合同负债 120.4 亿(+46% 环比)
2026-07-29 [融资·→] 定增 4794 万股落地
2026-05-20 [订单·↑] 新接 207 艘船，高附加值占 72%
2026-03-12 [减持·↓] 股东拟减持不超 2%
...
筛选：[订单] [融资] [筹码(减持/解禁/质押)] [业绩] [风险]   方向：↑利好 ↓利空 →中性
```
- 事件抽取：规则层（标题关键词分类）+ LLM 层（正文结构化抽取，schema 见 §8.3）
- **影响方向标注（↑↓→）的克制设计**（合规核心，详见 §8.4）：AI 给方向 + 一句依据 + 置信度；用户可一键改判（用户判定优先展示）；显著位置固定免责声明
- 每条事件强制带源（文档名 + 页码/公告链接），一键跳原文核验

**F8.3 跨期科目追踪**：
```
"合同负债" 近 5 期：
2025Q3: 50.7亿 → Q4: 53.5亿 → 2026Q1: 82.7亿 → Q2: 120.4亿 (环比 +46%)
AI 注解：连续 4 期上升，在手订单扩张信号 [引：各期财报页码]
```
- 数据来自各期财报预处理的数字索引，按科目聚合；**科目别名映射表**处理跨期科目名漂移（预收款项→合同负债等重分类），映射开放可编辑

**F8.4 实体追踪**（读通鉴"人物 ID 化"的移植）：
- 子公司/大客户/供应商/产品线/募投项目 ID 化，档案页可查"该实体在各期财报/公告中的全部出现位置"
- 首期只做**公司内实体**（跨公司实体图谱是远期）

### F9 账户 / 配额 / BYOK

- **认证**：邮箱+密码；GitHub OAuth
- **分层**（学读通鉴的 freemium）：
  - 匿名：纯前端阅读 + 数字换算（不耗服务端 LLM）
  - 注册免费：每月配额（如 30 份文档 AI 预处理 + 500 次问答 + 3 个标的档案）
  - BYOK：自填 LLM key（GLM/OpenAI/Claude）→ 配额无限，成本归用户
- **BYOK 安全**：key 用 Supabase Vault 加密存储，**服务端代理调用**，key 永不下发浏览器（避开泄露与 CORS 双坑）
- 存储：文档库默认 200MB/500 份（条目数配额优先于字节配额，公共公告 hash 去重后实际占用极小）

## 5. 核心用户流程

**流程 1 · 新用户 5 分钟上手**：
落地页 → 内置演示财报（免注册，知名公司年报，已预处理好）→ 体验阅读/悬浮/速览 → "导入你自己的财报" → 注册 → 拉取第一家公司全部历史 → 引导建标的档案。

**流程 2 · 读一份财报**：
文档库打开 PDF → 目录侧栏跳"重要提示"和"主要会计数据" → 逐页速览扫全篇 → 停在感兴趣页深读，数字悬浮 + 划词问答 → 高亮/笔记 → 读完点"综合保存" → AI 综合卡入档。

**流程 3 · 建立跟踪**：
搜索标的 → 一键拉取全部历史财报+公告 → 生成标的档案 → 看时间轴纵览 → 下季财报发布后拉新入库 → 时间轴自动延长，跨期科目序列自动续上。

**流程 4 · 决策支撑**：
开标的档案 → 筛"订单+业绩"看利好链 → 筛"筹码"看减持/解禁 → 跨期科目看合同负债/应收/存货趋势 → 每条存疑事件点回原文核验 → 自己下判断，可把判断写成档案页的"我的结论"笔记。

## 6. 数据模型

### 6.1 实体关系（简化 ER）

```
User ─< LibraryEntry >── Document ──────▶ DocObject(内容寻址, hash 主键, 全站共享)
                 │                          │
                 │                          ├─< PageText(逐页文本层)
                 │                          ├─< PageDigest(逐页速览, LLM)
                 │                          └─< NumberIndex(数字索引, 程序抽取)
                 │
                 ├─< Annotation(批注/高亮, 页坐标)
                 ├─< Note(笔记)
                 └─< ReadProgress

Ticker(标的) ─< Document(归组)
           ├─< Event(事件, 来自公告/财报抽取) ──▶ 源 Document+页码
           ├─< MetricSeries(科目时序, 聚合自 NumberIndex)
           └─< Entity(实体) ─< EntityMention(出现位置)
```

### 6.2 关键设计：内容寻址共享（成本命脉）

- `DocObject` 以文件内容 hash 为主键：巨潮公告是公共数据，100 个用户导入同一份中报，**PDF 与全部预处理产物（文本层/速览/数字索引）全站只算一份**——第二个用户导入时秒开且零 LLM 成本
- 访问控制：用户须有自己的 LibraryEntry（自己导入/拉取的动作）才能读取该 DocObject——共享的是"缓存"，不是"分发"（合规口径见 §9）
- R2 免费 10GB + 去重 ≈ 数万份财报容量，免费层够跑到远超验证期

### 6.3 事件 schema（LLM 抽取目标）

```json
{
  "date": "2026-09-01",
  "type": "order | financing | chip(减持/解禁/质押) | earnings | risk | other",
  "title": "新接 10 亿美元 PCTC 船订单",
  "entities": ["广船国际"],
  "amount": {"value": 1e8, "currency": "USD"},
  "direction": "positive | negative | neutral",
  "direction_reason": "在手订单扩充，交付排期至 2029 年",
  "confidence": 0.85,
  "source": {"doc": "2026-09-01 公告", "page": 1, "url": "cninfo..."}
}
```

### 6.4 科目别名映射

- 系统表：标准科目树（营收/归母/扣非/合同负债/应收/存货/毛利率…）
- 每标的可有用户可见可编辑的别名映射（处理"预收款项→合同负债"式重分类与口径微调）
- 聚合时展示映射提示，不静默合并

### 7.1 总体（云部署版，继承 v2 修订）

```
   │          │              │

```

### 7.2 存储：PDF 存到哪里（用户核心疑问，正面回答）

| 形态 | PDF 存储 | 预处理产物 | 说明 |
|---|---|---|---|
| 云端 | **Cloudflare R2**（10GB 免费，零出口费），hash 去重 | R2（JSON，随 DocObject） | 用户配额按 LibraryEntry 条目计 |
| 自部署 | 本地磁盘（docker volume） | 同盘 `data/` 目录 | `docker-compose up` 即用，零云依赖 |

### 7.3 AI 管道：程序层与 LLM 层严格分离（成本第二命脉）

```
PDF ──pypdf──▶ 逐页文本层 ──正则/规则──▶ 数字索引+科目定位     【程序层：零 LLM 成本】
                                        │
              逐页速览(每页1次LLM) ◀─────┤                      【LLM层：按需+缓存】
              事件抽取(每公告1次LLM)      │
              综合卡/导读/问答(按用户动作) │
                                        └──▶ 全部产物挂 DocObject 全站共享缓存
```

- v2 成本模型（0.5 元/份）成立的**前提**就是数字索引走程序层——M1 实施红线，写死在架构里
- 逐页速览/事件抽取结果全站缓存（hash 命中即免），重复阅读零边际成本
- 最坏估计（继承 v2）：100 活跃用户 × 月 10 份新财报 ≈ 500 元/月平台 key；BYOK 分流后实际百元级

## 8. AI 设计原则

### 8.1 四铁律
1. 伴读不替读（原文恒在，AI 是侧栏/悬浮/注）
2. 有据必引（页码/公告链接，无据即"不知道"）
3. 数字程序算（LLM 永远不做算术，只解释程序算好的数）
4. 整理不荐股（方向标注 + 依据 + 用户改判权，永不出现买卖建议措辞）

### 8.2 防幻觉机制
- 问答上下文只喂当前页±2 页原文（或检索片段），不靠模型"记忆"
- 事件/数字抽取后**回显校验**：抽取值必须能在原文片段中找到，找不到即丢弃进待确认区
- 每条 AI 产物带"核验原文"跳转，用户反馈错即标记并从时间轴降权

### 8.3 抽疑不抽定
低置信度（<0.7）事件不直接进时间轴主视图，进"待确认"折叠区，用户确认后转正——读通鉴"371 岁满宠"教训的制度化。

### 8.4 影响方向（利好/利空）标注的合规设计
- UI 措辞：**"影响方向：偏多 ↑ / 偏空 ↓ / 中性 →"**，绝不出现"买入/卖出/建议"字样
- 每个方向必附一句依据 + 源引用；用户改判优先展示（"你认为中性"）
- 档案页与时间轴固定挂免责声明："本页为公开信息之机器整理，不构成任何投资建议；数据以巨潮原文为准"
- 产品页脚全站免责声明 + AIGC 内容统一标识

## 9. 合规与风险

| 风险 | 对策 |
|---|---|
| **投顾牌照边界**（时间轴"利好利空"最敏感） | §8.4 全套设计：方向=信息整理属性、依据强制、用户改判、免责声明、永不出现买卖措辞；上线前对照《证券投资顾问业务暂行规定》自查一遍 |
| **AIGC 标识义务**（《人工智能生成合成内容标识办法》2025-09 已施行） | 所有 AI 输出（速览/问答/注/事件/综合卡）统一挂显式"AI 生成"标识 |
| 巨潮接口限流/封禁 | 接口层抽象可换源；hash 缓存已下载公告；失败降级手动上传；监控告警 |
| LLM 成本滥用 | 配额+速率限制+BYOK 引导+单文档预算上限+全站缓存去重 |
| Serverless 时限 vs 预处理 | 逐页短任务链式自触发（v2 方案 b）；单页失败独立重试 |
| 数据合规（转载边界） | 只存用户自主导入/拉取的公开公告；hash 共享定位为"缓存"而非"分发库"；引用页指向巨潮原文 |
| Supabase 免费层 7 天不活跃自动暂停 | GitHub Actions 每日定时 health check 保活（上线第一周就配） |
| Vercel Hobby 禁商用 | 云主站声明"非商业演示"或预留 $20/月 Pro 预算；自部署文档不受影响 |
| 与 MinerU 重复建设 | 可插拔解析引擎定位，MinerU 是可选依赖 |
| 幻觉（梳理场景敏感） | §8.2 全套 + 用户反馈纠错入口 |
