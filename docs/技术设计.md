## 1. 架构总览

```
┌─ 前端 SPA/PWA（Next.js App Router + TS + Tailwind，Vercel/自部署）────┐
│ 阅读器(PDF.js canvas+文本层+叠加层) / 文档库 / 标的档案与时间轴 / 账户    │
└──────────────┬────────────────────────────────────┘
┌─ API 层（Next.js Route Handlers，Node runtime）───────────────────┐
│ documents CRUD  cninfo(搜索/下载)  ask/events(后续)                 │
└──┬─────────────────────┬──────────────────────┬────────────┘
   │                     │                      │
┌─ 存储层（可插拔接口）───┐ ┌─ 对象存储 ────────┐ ┌─ LLM 网关（薄抽象）──┐
│ 元数据：JSON(自部署)    │ │ PDF+预处理JSON     │ │ GLM 默认 / BYOK 可换  │
│        Supabase(云版)  │ │ R2(云) / 本地盘(自) │ │ 统一接口防锁定        │
└───────────────────────┘ └───────────────────┘ └────────────────────┘
```

**模块划分**：`src/core/`（纯函数核心：数字句读/元信息解析/巨潮筛选——零依赖可单测）+ `src/core/store/`（存储接口与实现）+ `src/app/`（页面与 API）+ `src/components/`（阅读器等客户端组件）。开源后对应规划 `apps/web` + `packages/core` 的仓库结构。

## 2. 数据模型

```
Document（元数据条目）
  id, title, company, year, docType(年报|半年报|一季报|三季报|招股书|公告|其他),
  source(upload|cninfo), sourceUrl?, size, addedAt, fileName, hash(内容寻址)
DocObject（物理对象，hash 主键）
  pdf 文件 + 逐页文本层 + 数字索引 + 速览（M2 起）——全站共享，第二人导入零成本
Annotation / Note / ReadProgress（挂 Document+页坐标）
Ticker（标的档案）：company 归组 → Event[]（时间轴）/ MetricSeries[]（科目时序）/ Entity[]
Event schema：
  { date, type: order|financing|chip|earnings|risk|other, title, entities[],
    amount?, direction: positive|negative|neutral, direction_reason,
    confidence, source:{doc,page,url} }
```

**内容寻址去重是成本命脉**：公共公告是同一份文件，100 人导入只存一份 PDF 与一份预处理产物。访问控制上，用户须有自己的 Document 条目（导入动作）方可读取——共享的是缓存，不是分发（合规口径）。

## 3. PDF 管道

```
PDF → pdfjs-dist 渲染（canvas 原版面 + TextLayer 文本层，两层像素对齐）
    → 文本层承担：文本选中（划词）/ 命中测试 / 语义叠加高亮（对 span 加 class）
    → 数字句读：正则识别长数字（千分位组或≥7位）→ 纯前端换算卡片
    → M2：逐页 getTextContent 入库 → 数字索引（程序层）→ 同比层/科目追踪
```

要点：
- 文本层与 canvas 使用同一 viewport scale，保证选区与视觉对齐（F1-AC1.4）
- 数字高亮三模式（线条/颜色/全关）只改 CSS class，零重渲染
- 预处理拆成**每页一个短任务**（Serverless 时限解法），链式自触发、断点续跑、单页失败独立重试

## 4. 巨潮集成（cninfo）

| 项 | 设计 |
|---|---|
| 股票检索 | POST `/new/information/topSearch/detailOfQuery`（form: keyWord）→ 候选 {code, orgId, name} |
| 公告查询 | POST `/new/hisAnnouncement/query`（form: column 按交易所、stock=`code,orgId`、category、**seDate**） |
| **参数红线** | 日期参数只认 `seDate`（`startDate/endDate` 会被静默忽略——生产实测教训），且返回结果仍需客户端按日期过滤复核 |
| 财报正本筛选 | 规则层：必含`年度报告|半年度报告|第一季度报告|第三季度报告`；排除`摘要|英文|更正|补充|取消|修订|说明会|路演|索引…`（测试覆盖） |
| PDF 下载 | `static.cninfo.com.cn/finalpage/...` → 校验 `%PDF-` 头 → 落库；同 sourceUrl 去重 |
| 限流对策 | 单飞（进行中请求复用）、hash/sourceUrl 缓存、失败降级手动上传、超时 15s |

## 5. AI 管道：程序层与 LLM 层严格分离

```
程序层（零 LLM 成本）           LLM 层（按需 + 全站缓存）
─────────────────              ─────────────────────────
数字句读换算（前端）             逐页速览（每页 1 次）
逐页文本层抽取（pdfjs）          事件抽取（每公告 1 次）
数字索引/科目定位（规则）         导读注/框架注/问答/综合卡（用户动作触发）
同比环比统计                    ↑ 全部产物挂 DocObject hash 共享
```

**红线**：数字索引必须程序层（正则+文本层），成本模型（≈0.5 元/份）成立的前提；LLM 永不做算术。

**防幻觉三机制**（进 prompt 模板与代码）：
1. 上下文只喂当前页±2 页或检索片段，不靠模型记忆
2. 抽取回显校验：事件/数字必须能在原文片段找到，否则丢弃
3. READ_FAILED 硬规则：未读到依据必须回答"原文中没有找到依据"（生产实测：模型没读到文件时会编造，必须显式约束）

**抽疑不抽定**：置信度 <0.7 的事件进"待确认"折叠区，用户确认后转正——脏数据不进主时间轴。

## 6. 存储与部署矩阵

| 形态 | 元数据 | PDF/产物 | 认证 |

云版免费层注意：Supabase 项目 7 天无活动自动暂停 → GitHub Actions 每日 health check 保活；Vercel Hobby 禁商用 → 主站声明非商业或预留 Pro 预算。

## 7. 安全

- 上传校验：`%PDF-` 魔数 + 大小上限（100MB）+ 类型白名单
- 巨潮下载仅接受 `static.cninfo.com.cn` 前缀 URL（防 SSRF）
- BYOK（M4）：key 入 Supabase Vault 加密，服务端代理调用，任何 API 响应不含 key
- RLS：Document/Annotation 按用户隔离（云版）

## 9. 成本模型（云版最坏估计）

100 活跃用户 × 月 10 份新财报 × 0.5 元 LLM = 500 元/月；hash 去重 + BYOK 分流（预估 70% 重度用户自带 key）后实际百元级；基础设施全部免费层。超出则收紧配额。
